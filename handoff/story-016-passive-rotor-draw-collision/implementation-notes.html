Core implementation

Implemented. Rotor torque samples cardinal sand contacts on the current raster before source emission and SandSimulation.Step. The reaction force direction and pivot-to-contact lever arm produce signed torque. Composite cross inertia uses resolved dimensions, then profile damping, speed cap, and deterministic rest snap are applied. Legacy degreesPerSecond stays serialized but does not drive motion.

Each angular update is subdivided by collisionSweepStepDegrees and a half-cell arc bound. Any candidate raster touching committed DynamicMask stops at the previous valid angle and clears angular velocity. Grain displacement is planned before mutation into unique adjacent cells outside validity/static/cup/draw/current/future/swept rotor geometry; no safe cell means the rotor step rolls back and keeps every grain. Shade, velocity, momentum, material, counts, and stroke mask are preserved.

DrawStrokeCollisionResolver is shared by live pointer acceptance and commit. It samples long pointer segments at half-cell intervals and tests the same effective radius against board validity, static/cup/draw/rotor masks and resolved SourceDomain size/body offset. GameplayInputController latches first contact for the gesture. Commit revalidates the accepted path, consumes only accepted length, and stamps only that path. Preview and committed visuals now receive the same effective thickness.

Performance

For Level_01, the simulation grid is 180x320 = 57,600 cells at 0.06 cell size. One rotor reserves four byte-per-cell scratch masks (~225 KiB), rotor/grain lists (~242 KiB using the bounded 6,889-cell raster capacity), and bounded search arrays (~4.9 KiB): about 472 KiB additional level memory, plus list headers. The draw path adds one reusable 128-point Vector2 buffer (~1 KiB); pointer input already owns its corresponding buffer.

After the idle fast path, a stationary rotor performs contact-face sampling and integration without rerasterizing. A moving Level_01 rotor is capped at about 6 angular samples per 60 Hz step (2-degree setting plus half-cell arc limit); each sample scans a bounded raster box of at most about 6,889 cells. Work scales with rotor count, swept angle, and contact/swept cells. All simulation and pointer resolver scratch is allocated at level setup; no per-step/per-sample managed allocation is intended. GPU and draw calls do not change. Redmi 9A runtime profiling was not available, so the moving-contact worst case still needs device measurement.
